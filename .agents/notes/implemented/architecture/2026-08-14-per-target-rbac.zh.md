# Agent Note：逐目标 RBAC

状态：已实现

[English](2026-08-14-per-target-rbac.md) | 中文

## 问题

多节点控制平面不能把全局 `developer` 或 `operator` 角色视为对每台已注册服务器的授权。仅在 Web 中隐藏未授权行并不充分，因为直接 Remote 调用、会话创建、工作树操作和部署执行仍可指定目标 id。

## 决策

全局角色仍是用户可行使的最高权限。每位非管理员用户还必须拥有精确目标的持久授权，其上限是 `read`、`operate`、`configure` 或 `administer`。管理员保留对所有目标的访问权，以便恢复和管理授权。

Inventory 按当前 actor 过滤目标与 plan 列表，然后在每个目标特定的服务操作内部重新检查授权。读取、健康检查、工作树、执行世界路由、目标变更、plan 创建、审批、执行和删除都不能依赖列表过滤。授权变更使用已观察 revision，验证目标和用户存在，并追加安全审计记录。创建目标会为创建者写入显式管理员授权，即使全局管理员不依赖该记录。

Web 部署页挂载生成的授权 Remote 操作。管理员选择目标、用户和权限上限后，无需访问数据库即可修改或撤销授权。

## 考虑过的替代方案

**在目标标签中编码访问权。** 已拒绝，因为标签是用户控制的元数据，不具备带 revision 的主体身份或授权操作。

**仅使用全局角色。** 已拒绝，因为只负责一个项目的 operator 会获得全部 SSH 或容器目标的凭据与执行权。

**只在列出目标时授权。** 已拒绝，因为不透明 id 可能被保留或猜中，每个操作都必须执行自身作出的决策。

## 结果

一个 SivitaCode Web 进程可以管理多个项目和服务器，而无需让每位已认证开发者访问全部目标。授权绑定本地用户；外部目录用户组和 OIDC claim 需要独立身份提供方。ACP stdio 不携带已认证 SivitaCode actor，因此继续使用进程 allowlist。
