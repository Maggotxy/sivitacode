# Agent Note：Web 身份管理

状态：已实现

[English](2026-08-14-web-identity-administration.md) | 中文

## 问题

SivitaCode 的访问控制 domain 已经持有持久用户、角色、会话撤销和安全审计。如果继续把读取操作保留为未受保护的进程内方法，授权将依赖每个未来传输包装器，而且第二位管理员没有产品控制面可用。

## 决策

访问控制是生成式 Typert Remote 服务。每个身份与审计操作都会在读取或改变持久状态前，于服务方法内部执行 `administer` 授权。Web 设置页挂载该 namespace，并提供用户创建、单角色分配、账户启停和有界的最近审计视图。

角色与停用状态变更会递增目标用户的会话版本，使现有会话失效。服务在变更提交点统计已启用管理员，并拒绝停用或降级最后一位管理员。该拒绝以及成功变更都会追加持久审计记录。密码哈希、会话 token 和凭据材料绝不进入 Remote 结果。

## 考虑过的替代方案

**仅在 Web 组件或 API 网关授权。** 已拒绝，因为 ACP、插件或未来传输可能绕过该包装器调用服务。

**允许删除最后一位管理员并依靠环境变量重新引导。** 已拒绝，因为用户表非空后会刻意忽略引导值；普通 UI 操作将可能使部署无法恢复。

**在首版 Web 表单中暴露任意角色数组。** 服务支持非空角色集合，初始 UI 则为每位用户选择一个内置角色，使权限变更易于审查。后续增加角色组合 UI 不需要改变存储。

## 结果

浏览器无需编辑 SQLite 或重启服务即可管理多用户部署。只有管理员能够发现用户或审计记录。内置角色仍是全局权限上限；逐目标授权策略由 Deployment Inventory 独立负责。

## 验证

服务测试覆盖读取拒绝、角色变更撤销、最后管理员保护、有界审计读取和持久拒绝记录。客户端测试覆盖生成 Remote 注入与设置页注册。类型生成、Web 组合测试、文档配对、lint 和仓库卫生检查覆盖组装路径。
