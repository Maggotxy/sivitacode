# Agent Note: SivitaCode 产品入口

Status: implemented

[English](2026-08-13-sivitacode-product-entry.md) | 中文

## Problem

本仓库需要独立运营 SivitaCode 产品，同时不能掩盖 DeepSeek Harness 核心的来源。复用 `dsh` 命令和数据根目录会混合用户数据，并让产品行为依赖兼容约定；全局修改内部包名则会显著提高审查上游安全更新的成本，也可能暗示未修改代码由 SivitaCode 创作。

## Decision

**两个可执行入口共用同一运行时。** 软件包通过独立的轻量入口发布 `sivitacode`，并保留 `dsh` 兼容可执行文件。独立入口在导入共享调度器前选择产品身份，因此符号链接解析不会选错产品。

**SivitaCode 使用隔离的数据根目录。** 启动前，`SIVITACODE_HOME`（未设置时为 `~/.sivitacode`）会映射到核心现有的数据根目录解析器。兼容入口继续解析 `DSH_HOME` 或 `~/.dsh`。项目和数据根目录中的 `.env` 文件都不能设置任一产品的启动变量。

**产品命令优先支持 Web 与无头运行。** `sivitacode web` 启动 Web profile，`sivitacode run <任务>` 启动无头 profile。通用 `--profile` 和插件管理接口继续用于组合与兼容。

**内部上游包名保持来源可追溯。** 未修改和共享的核心包保留 `@deepseek-ai/dsh-*` 名称及 MIT 署名。整个发行物共用的静态浏览器产物使用 SivitaCode 标题。仅当使用 SivitaCode 入口时，命令帮助、运行时提示和就绪信息才使用 SivitaCode 身份；兼容入口保留 DSH 文本。

**公开身份由产品拥有。** Sivita Pulse 标记将执行单元与连续 S 路径组合在一起，内置紫罗兰／青色配色分别表示推理和执行信号。Web 应用、文档站、favicon、PWA 元数据和字标使用相同的几何图形与颜色角色，不复用上游图形资产。

**源码和服务器产物是主要公开分发方式。** 公开 Git 仓库保留完整 MIT 历史和声明。带标签的 release 会附加经过验证的 Linux 与 macOS 平台专用服务器归档，以及会验证摘要的安装器；用户无需访问内部 npm 包依赖图。npm 只作为可选启动器渠道，不作为来源或部署权威。

## Alternatives considered

**全局修改所有上游包名。** 不采用，因为这会产生长期且巨大的合并成本、弱化来源信息，同时不会增加执行能力。

**用单一的新命令完全替换 `dsh`。** 不采用，因为这会破坏上游对照和第三方插件工作流，并促使新旧产品数据共用一个根目录。

**根据 npm 生成的符号链接推断身份。** 不采用，因为启动器和包管理器可能暴露链接名称，也可能暴露解析后的 JavaScript 路径。独立标记入口在直接执行、npm、pnpm 和容器环境中都具有确定性。

**在新 npm scope 下发布完整内部包依赖图。** 不采用，因为机械调整 scope 会弱化上游来源信息，并使每次上游更新都变成包身份迁移。经过验证的服务器归档无需在 registry 发布共享内部实现，即可携带完整运行时。

## Consequences

SivitaCode 可以发布自己的命令、数据根目录、用户可见身份和未来配置，同时不把上游核心误述为原创。同一产物仍可测试兼容性。共享内部实现继续使用 DSH 命名的环境和包接口，因此未来若要调整作用域，必须进行明确迁移，而不能由品牌变更隐式完成。

发布安装验证会使用纯 Node 驱动打包后的两个可执行入口，并要求每个入口都报告打包版本。这样兼容入口就无法掩盖 SivitaCode 产品入口缺失或损坏的问题。

公开 release 比轻量 registry 启动器更大，但一个不可变归档包含通过认证、Web、ACP、原生沙箱和离线安装检查的准确运行时。GitHub release 发布会等待全部受支持平台任务，并能在不改变产物名称的情况下重复执行。
