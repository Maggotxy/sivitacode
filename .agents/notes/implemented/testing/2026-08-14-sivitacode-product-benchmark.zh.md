# Agent Note：SivitaCode 产品基准

Status: implemented

[English](2026-08-14-sivitacode-product-benchmark.md) | 中文

## 问题

SivitaCode 需要可重复的构建后产品启动与完整 agent 验收证据。没有样本、环境事实或匹配基线的单次墙钟数值，无法区分产品回退与宿主差异。启动速度也不能证明 agent 任务质量。

## 决策

基准在可配置预热后运行三个确定性的构建入口场景，并把每次观测、中位数和 nearest-rank p95 写入带版本的 JSON。它还使用确定性 mock 模型运行真实构建模式 headless Loader 验收，覆盖 Bash 工具调用与持久会话断言。报告记录 Node 和操作系统环境。

基线执行采用显式方式而不是自动方式。调用方提供来自等价基础设施的报告和允许的中位数最大回退百分比。基准会拒绝缺失场景或超预算中位数。托管 CI 的定时任务只采集 artifact，不比较不同的临时机器；手动工作流接受明确的先前 run id 来执行预算。

## 考虑过的替代方案

**提交一个固定延迟阈值。** 不采用，因为 runner 硬件、电源状态、Node 版本和并发负载会让绝对阈值变成噪声。

**把无密钥 mock 验收称为 agent 质量基准。** 不采用，因为它证明产品组合和工具执行，不证明代表性编程任务成功率或真实模型方差。

**比较 SivitaCode 与兼容命令。** 不采用，因为两个入口有意共享同一运行时；这种比较只会测量品牌调度，而不是架构方案。

## 后果

维护者可以归档可比较的机器可读证据并拒绝测得的回退，同时不会把宿主特定数值宣传成普遍性能。只有具备固定语料、真实模型/provider 协议、多次试验、成本核算和统计分析后，才能提出 agent 质量比较。
